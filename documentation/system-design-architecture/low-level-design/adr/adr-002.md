ADR-002: ESTRATÉGIA DE AUTENTICAÇÃO E AUTORIZAÇÃO

Status: Aceito
Data: 26-10-2026
Contexto: Sistema tem 3 papéis diferentes: ADMIN (direção edita tudo, vê financeiro global), STAFF (engenheiro atualiza status e custos), CLIENT (cliente final só vê seus projetos). Precisa ser seguro para B2B, mas com custo zero no MVP. Não pode ter vazamento CS04.

Decisão: Usar JWT auto-gerido + bcrypt + RolesGuard no NestJS + Redis para rate limit e blacklist

Justificativa:
1. Custo zero: Auth0, Clerk, Supabase Auth cobram por MAU e não permitem customizar empresaId facilmente. JWT próprio = 0 Kz no MVP.
2. Multi-tenant seguro: No payload do JWT vamos colocar { userId, empresaId, role, email }. Todo Guard do NestJS lê empresaId do token e injeta no WHERE. Isso garante RN01 e CS04.
3. Bcrypt: Senhas com salt 10. Nunca salvar senha em texto. Padrão enterprise.
4. Expiração 8h (RNF02): Equilíbrio entre segurança B2B e não obrigar login toda hora. Refresh token fica para Fase 2 SaaS.
5. Redis para Rate Limit e Blacklist: Key ratelimit:login:{email} com INCR e TTL 60s - bloqueia 5 tentativas/min (RNF02). Key blacklist:jwt:{jti} com TTL igual ao token para logout imediato, sem precisar tabela no PSQL.

Consequências:
Positivas: Controle total, custo zero, multi-tenant nativo, seguro.
Negativas: Precisamos gerenciar emissão e validação de token. Mitigação: Usar @nestjs/jwt + Passport JWT.
Alternativas consideradas: Auth0 (descartado por custo $23/mês + complexidade empresaId), NextAuth (descartado por amarrar ao http://Next.js, precisamos no NestJS).
