

ADR-003: ARQUITETURA MONOLITO MODULAR (NÃO MICROSERVIÇOS)

*Status:* Aprovado
*Contexto:* Equipe de 1 dev, prazo até Fevereiro 2027, mas arquitetura precisa escalar para SaaS global com milhares de usuários. Alternativas: Microserviços desde o dia 1, Monolito desorganizado.

*Decisão:* Monolito Modular. Um único deploy NestJS, mas separado em módulos independentes: AuthModule, UserModule, PortfolioModule, ProjetosModule, SkillsModule, MensagensModule, MetricasModule, VagaAlvoModule.

*Por quê BigTech:*
- Monolito modular é o que Google, Shopify e Uber usaram no início. Microserviço com 1 dev é suicídio operacional.
- Cada Module tem seu Controller, Service, Entity, DTO. Se no futuro PortfolioModule precisar virar serviço separado, extraímos sem reescrever regra de negócio.
- Deploy único no Railway/Render, custo baixo.

*Consequências:*
- Positivo: Velocidade de desenvolvimento 3x maior que microserviços.
- Negativo: Se um módulo cair, tudo cai.
- Mitigação: Health check por módulo em /health e logs separados por módulo.
